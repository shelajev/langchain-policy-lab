# Host acceptance: native sandbox run of the single-file kit

This page lists the sandbox checks that only a host with Docker Sandboxes can
run, and records the host results at the end. The native run passed on
2026-11-13; the guide's source comments now say what each sandbox step was
verified with.

## Artifact

`examples/single-file-agent-kit/`, generated by the skill from
`examples/single-file-agent/` with
[single-file-agent.answers.json](../examples/single-file-agent.answers.json).
Check that `kit-manifest.json` output hashes match the files before running.

What is already checked without a sandbox (`bash scripts/check-single-file.sh`):
buildx build, `kit-tck` 19/19, and a composition probe that copies the kit
overlay onto the pinned `docker/sbx-kit-shell:1.0.0` image and runs the
`RUN.md` command with networking off, read-only, as uid 1000. That probe is
not evidence of sandbox policy or credential injection.

## Native checks

Run from `examples/` on a host with `sbx` (help checked against v0.53.0):

```bash
sbx run --detach shell --kit ./single-file-agent-kit --name single-file-agent-kit ./single-file-agent-kit
sbx policy ls
sbx exec -w /opt/single-file-agent-kit/app single-file-agent-kit /opt/single-file-agent-kit/venv/bin/python agent.py --fake-model
sbx exec single-file-agent-kit sh -c 'test -z "$(find /opt/single-file-agent-kit -name .env -o -name private -o -name id_rsa)" && echo no-private-files'
sbx exec single-file-agent-kit /opt/single-file-agent-kit/venv/bin/python -c "import urllib.request; urllib.request.urlopen('https://example.com', timeout=10)"
sbx policy log single-file-agent-kit
sbx secret set google --sandbox single-file-agent-kit
sbx exec -w /opt/single-file-agent-kit/app single-file-agent-kit /opt/single-file-agent-kit/venv/bin/python agent.py
sbx policy log single-file-agent-kit
sbx rm single-file-agent-kit
sbx secret ls --sandbox single-file-agent-kit
```

| Check | Pass condition |
| --- | --- |
| Create | Sandbox created from the local kit directory; record any approval prompt (none appeared in the host run) |
| Offline run | Exactly `{"category":"technical","ticket_id":"T-101"}` |
| Private files | `no-private-files` |
| Denied host | The request fails **and** `sbx policy log` shows a blocked `example.com` entry. A DNS, TLS or timeout error alone is not proof |
| Secret | `sbx secret set` prompts for the value; no `--token` |
| Live run | Output parses as JSON with `"ticket_id": "T-101"`; the log shows an allowed `generativelanguage.googleapis.com` entry. This shows the proxy injected the `google` secret the kit declares |
| Cleanup | `sbx rm` removes the sandbox and its scoped secret |

Cloud (`sbx --cloud run ... --kit`) and publishing to a registry are optional
and not part of this acceptance. They stay unverified (not run).
